# 微信小游戏优先架构

## 目标

项目主开发目标调整为轻量级微信小游戏：从首页到每一章剧情交互，都可以直接在微信开发者工具中打开、刷新、调试。

## 新主线

`minigame/` 是新的主入口。

- 使用微信小游戏原生 Canvas。
- 不依赖 DOM、React、Vite。
- 不需要 Unity 构建即可在微信开发者工具中调试。
- 第一阶段先做 2D/伪 3D 场景和交互，保证章节玩法快速迭代。

## 目录职责

- `minigame/`
  - 微信开发者工具直接导入的小游戏项目。
  - 承载首页、故事模式、自由模式和章节交互。
- `docs/design/steps/`
  - 每一步设计思路和验收标准。
- `docs/`
  - 剧情、架构、玩法设计文档。
- `unity/`
  - 继续保留，用于 3D 模型验证、高配场景预研和后续可能的 Unity 版本。
- `src/`
  - 原 Web/Vite 原型，后续可作为逻辑参考，但不再是主调试入口。

## 为什么不继续以 Unity exe 为主

Unity exe 适合验证 3D 效果，但不适合章节快速调试：

- 每次构建成本高。
- 微信开发者工具链路更长。
- 小游戏包体、加载和兼容性压力更大。

当前阶段更适合先把玩法闭环做轻：首页、章节、角色行动、资源反馈、事件日志先跑通，后续再逐步替换更精美的 3D 表现。

## 阶段路线

1. `M1`：微信开发者工具可打开，首页可进入故事模式。
2. `M2`：第一回完整交互闭环。
3. `M3`：前 10 回章节数据化。
4. `M4`：客栈区域、人物站位、事件动画增强。
5. `M5`：接入资源管理、存档、音效和真机性能优化。
