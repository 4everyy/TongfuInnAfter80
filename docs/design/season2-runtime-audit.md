## 结论

当前画面已经达到可继续开发的垂直切片质量：探索区由 490 扩至 574 逻辑像素，右侧账本缩至 270，角色、摇杆、操作按钮与胶囊安全区没有重叠。水巷分店背景能够在微信 Canvas 中真实加载，不会回退到色块占位。

## 流程步骤

1. **进入水巷分店探索：健康**
   - 正式背景已加载，分店柜台、后厨、客房楼梯和临水区域可辨。
   - 场景宽度提升后，角色前方保留了足够的移动和热点观察空间。

2. **读取当前目标：健康**
   - 右侧账本只保留任务目标和队伍入口，没有重复显示场景热点文案。
   - 270 像素宽度下，目标正文仍能保持两行以内。

3. **移动与交互：健康**
   - 摇杆外圈、底色和阴影已经减轻，命中区仍大于 44 逻辑像素。
   - 三个底部按钮与场景边界相对定位，在 574 像素探索区内没有压住账本。
   - 角色脚底阴影保持低透明椭圆，没有出现方形底色。

4. **人物与场景融合：基本健康**
   - 角色高度和地面接触关系合理，未出现方形底色或明显悬浮。
   - 李大嘴已经接入侧向、正向、背向三套正式图集；八帧步态左右脚交替，围裙、葫芦与厨具袋保持同侧。
   - 河市截图中李大嘴的宽肩厚背轮廓与临时灶台形成明确职业联系，人物尺度与佟湘玉一致但体型可辨。
   - 首轮检查发现渡口人物脚底落到水面，已将渡口背景纵向偏移由 `-283` 校准为 `-145`；复核截图中人物已落在湿木栈桥上。
   - 码头纵向偏移校准为 `-210`，人物与石质装卸路面保持同一地面线。
   - 分店中人物靠近中桌时，碰撞应继续阻止脚底胶囊进入桌体；开发者工具实走时需验证人物不会始终绘制在所有桌椅前方。

5. **分店经营：健康**
   - 管理模式保留 500 像素宽场景和宽账本，探索模式的窄账本不会压缩菜单、排班与客房信息。
   - 五名已解锁经营角色在场景中保持独立站位，没有互相重叠。
   - 分店标题、日期、资源栏、七个账本页签和主要按钮均避开微信胶囊区域。

## 最高优先级建议

- 在开发者工具中实走水巷分店、河市和渡口，重点检查桌椅、货箱、棚柱前后的遮挡切换。
- 在开发者工具中观察李大嘴八帧循环的实际速度与位移匹配，重点排除滑步。
- 交互热点出现时继续保持“场景中一个主要提示”，不要在账本中重复同一句话。

## 证据限制

本轮截图由小游戏同一 Canvas 渲染器离线生成，已加载真实分包资源和安全区参数。静态截图可以验证尺度、基线和遮挡结果，但不能证明八帧播放节奏、多点触控或真机帧率；这些项目仍需在已打开的微信开发者工具 GUI 中确认。
