# 白展堂高级动画小样

## 目标

先只验证白展堂一个角色的“真实走路”链路：静态模型转为带骨骼角色，再得到站立、行走、跑动等动作资源，最后接入微信小游戏横屏探索。

## 当前结论

`unity/Assets/Art/ImportedModels/Characters/zhantang` 里的模型当前是静态模型：

- GLB 没有 `skins / joints / animations`
- FBX 没有 `Skin / Cluster / LimbNode / AnimationStack`
- OBJ 只能作为静态网格使用

因此现有模型不能直接播放腿部动作，必须先做 rigging。

## 验收标准

1. 模型必须存在骨骼：`skins > 0`、`joints > 0`。
2. 行走动画必须有清晰腿部交替迈步，不只是整体位移。
3. 白展堂应面向 glTF 的 `+Z` 方向，避免进入游戏后方向反转。
4. 微信小游戏内单角色预览目标：横屏 30 FPS，白展堂移动时动画切换无明显卡顿。
5. 包体策略优先轻量化：小样阶段只接白展堂，不复制九人资源。

## 接入路线

### 第一阶段：资源骨骼化

使用 Meshy Rigging API 或 Blender/Mixamo 将白展堂 GLB 转为带骨骼模型。

准备命令：

```powershell
python .\tools\inspect_character_rig.py --character zhantang
python .\tools\meshy_zhantang_rigging_sample.py
```

提交 Meshy 任务时优先使用公开 GLB 地址：

```powershell
python .\tools\meshy_zhantang_rigging_sample.py --submit --model-url <public_glb_url>
```

当前本地 GLB 约 41.7MB，不建议直接用 Data URI 提交。

本次小样已验证 Data URI 也能提交成功，但后续批量角色仍建议使用公开模型地址或压缩后提交，避免大请求不稳定。

### 第二阶段：小游戏播放小样

拿到 `zhantang_walk.glb` 后再决定：

- 路线 A：小游戏 Three.js 实时 3D，直接播放 GLB 骨骼动画。
- 路线 B：Unity/Blender 离线渲染序列帧，小游戏使用 2D spritesheet 播放。

白展堂先走路线 A 做压力测试；如果微信端帧率或包体不理想，再切到路线 B。

### 第三阶段：游戏状态机

白展堂探索状态拆为：

- `idle`：原地站立
- `walk`：方向移动
- `interact`：靠近目标交互
- `alert`：听到屋顶脚步
- `dash`：轻功闪身，后续技能用

当前横屏探索系统里的移动、场景、剧情节点可以保留，只替换人物绘制层。
