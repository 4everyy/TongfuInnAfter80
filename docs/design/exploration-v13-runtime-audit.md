# 探索场景融合与 HUD v13 运行审核

审核基准为 `844 × 390` 微信小游戏逻辑画布。

## 第 1 步：修复前探索画面

状态：需要修复。

- 人物脚底落在柜台和桌面区域，场景深度关系不可信。
- 固定右栏占用约三分之一画面，并重复展示任务、队伍和导航信息。
- 顶部四项资源依赖文字缩写，扫描速度慢。
- Canvas 通过 `fillText` 的 `maxWidth` 压缩中文，导致字号和字面宽度不一致。

证据：`D:\Temp\codex-clipboard-0f13af1c-951c-49a8-9552-f76e6c025b24.png`。

## 第 2 步：全宽探索与悬浮任务卡

状态：健康。

- 客栈柜台、楼梯、桌椅和出生点已经按正式背景重新校准。
- 佟湘玉脚底落在地砖上，柜台后 NPC 通过柜台前沿参与纵深遮挡。
- 探索场景恢复完整宽度，任务卡面积约占画布 6%，点击进入独立话本页。
- 底部移除客栈／账簿入口，仅保留队伍和动态交互。

证据：`outputs/product-design/exploration-v13-audit/01-inn-hotspot.png`。

## 第 3 步：字体与资源 HUD

状态：健康。

- 字体限定为 `20/16/12/10` 四级，并使用系统宋体风标题与系统无衬线正文。
- 文本采用测量、换行和省略号，不再横向压缩字形。
- 银两、食材、口碑、秩序使用四枚透明手绘图标，图标失效时回退为单字标识。
- HUD 依据微信胶囊左边界动态布局。

证据：`outputs/product-design/exploration-v13-audit/06-task-page.png`。

## 可访问性与限制

- 队伍、任务卡和资源图标命中区均不小于 `44` 逻辑像素，交互按钮为 `60`。
- 宣纸正文与墨色文字具有清楚对比；朱砂仅承担强调，不用于长段正文。
- 静态截图无法验证真实手指操作、逐字文本和呼吸动效，需要在开发者工具与真机补验。
